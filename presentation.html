Project Introduction
Slide 1 · Overview
SmartBank Assistant – AI‑Powered Banking Web Application

What is SmartBank Assistant?

A full‑stack banking web application that combines traditional digital banking (accounts, transactions, dashboard) with an AI‑powered chatbot built on Google Gemini, following AI‑First Software Engineering principles.

  • Core idea: Manage your bank accounts and ask questions in natural language.
  • SDLC approach: AI used in requirements, design, coding, testing, DevOps and documentation.
  • Deliverables: Frontend, backend, database, AI service, UML diagrams, report and documentation.

Based on: PROJECT_REPORT.md, PRESENTATION_SUMMARY.md, and the 13 weekly docs in docs/.

Technology Stack
Slide 2 · Tech Overview
Frontend (React + TypeScript)
Presentation Layer
  • React 18 + TypeScript for type‑safe UI (`frontend/src`).
  • Vite build tool and React Router for navigation.
  • Tailwind CSS and custom components for a responsive, modern design.
  • Pages: LoginPage, DashboardPage, AccountsPage, TransactionsPage, ChatPage.
Backend (FastAPI + PostgreSQL)
Application & Data
  • FastAPI REST API in backend/app with JWT auth and CRUD.
  • SQLAlchemy ORM and PostgreSQL (with SQLite dev fallback).
  • Google Gemini integration in services/gemini_service.py for AI chat.
  • Docker and docker-compose.yml for containerized deployment.

Backend – API Design
Slide 7 · FastAPI
Main Modules
backend/app
  • routes/auth.py – register, login, token refresh.
  • routes/account.py – list/create accounts, balances.
  • routes/transaction.py – CRUD for transactions.
  • routes/chat.py – AI chat endpoint with Gemini integration.
Typical Request Flow
Example
  1. Frontend calls /api/... with JWT token in the header.
  2. FastAPI dependency checks and decodes the token (auth/dependencies.py).
  3. CRUD layer in crud/ talks to the database via SQLAlchemy models.
  4. Response is serialized using Pydantic schemas in schemas/.
Data Model – Class Diagram View
Slide 8 · Domain Model

The class diagram (see 01-complete-class-diagram.puml) focuses on core banking entities and their relationships.

Main Entities
Database Models
  • User: login credentials, profile information.
  • Account: type (checking, savings, credit), balance, user owner.
  • Transaction: amount, type (deposit/withdraw/transfer), category, timestamp.
  • ChatLog: user id, messages, AI responses, timestamps.
Relationships
UML Summary
  • One User → many Accounts and many ChatLogs.
  • One Account → many Transactions.
  • Frontend components talk to backend via an APIService abstraction.
  • Routers use CRUD objects and GeminiService to handle logic.
User Journey – Sequence Diagram
Slide 9 · End‑to‑End Flow

The sequence diagram in 03-complete-sequence-diagram.puml describes how user actions move through the system.

Key Workflows
From UML_DIAGRAMS
  • Registration & Login: form validation → hash password → store user → issue JWT → redirect to dashboard.
  • Viewing Accounts: validate JWT → fetch accounts → return JSON → render cards on dashboard.
  • Creating Transactions: validate JWT → check balance → write transaction → update account → show confirmation.
  • AI Chat: store message → build context → call Gemini → store AI reply → update chat UI.

Ethics & Responsible AI
Slide 12 · Week 13

The docs/week13-ethics.md document shows how the app addresses bias, fairness, transparency, intellectual property and human‑in‑the‑loop practices.

Key Practices
Concepts
  • Bias monitoring – compare accuracy across user groups; flag differences > 15%.
  • Fair access – all authenticated users can use the chatbot, independent of demographics or balance.
  • Transparency – clear AI disclosure in the UI and API responses (ai_generated flag, model name, confidence).
  • Privacy – user context used only per‑request; not for training the underlying model.
Example Snippets
From week13‑ethics

    return {"bias_detected": True, "recommendation": "Review and retrain"}

How to Run the Application
Slide 14 · Practical

The project includes quick‑start scripts and documentation (README.md, RUNNING.md, QUICK_START.md) to make it easy to run a demo.

Using Scripts (Windows)
Simple path
  • Run setup.bat once to install dependencies and prepare the environment.
  • Use start-backend.bat to launch the FastAPI server.
  • Use start-frontend.bat to start the React dev server.
  • Open the browser at the URL shown in the terminal (usually http://localhost:5173).
Using Docker
Alternative
  • Build and start containers with docker-compose up --build.
  • Backend, frontend and database run in separate containers.
  • Good for consistent demos on different machines.
